The C++ file (`qcs6490_classify.cpp`) implements a complete inference pipeline using the **QNN C API** directly. Here's what each section does:

---

## 1. Load the QNN HTP backend (`dlopen`)

```cpp
void* lib = dlopen(backend_lib.c_str(), RTLD_NOW | RTLD_LOCAL);
QnnInterface_t* iface_ptr = get_qnn_interface(lib);
auto& qnn = iface_ptr->QNN_INTERFACE_VER_NAME;
```

Instead of linking against QNN statically, it loads `libQnnHtp.so` at runtime with `dlopen`. Then `get_qnn_interface()` walks the list of providers exposed by the library to find one with a compatible API version. The `qnn` variable is a struct of function pointers — every subsequent `qnn.xxx()` call goes through this vtable.

---

## 2. Initialize logging

```cpp
qnn.logCreate(log_cb, QNN_LOG_LEVEL_WARN, &log_handle);
```

Registers a callback that prints QNN internal warnings/errors to stderr. You can bump the level to `QNN_LOG_LEVEL_VERBOSE` when debugging.

---

## 3. Create the backend

```cpp
qnn.backendCreate(log_handle, backend_configs, &backend_handle);
```

This initializes the HTP backend itself — allocates internal state, verifies the Hexagon driver is present and reachable via FastRPC.

---

## 4. Create the device, pinned to QCS6490

```cpp
htp_dev_cfg.socInfo.socId = 35;   // QCS6490
qnn.deviceCreate(log_handle, dev_cfgs, &device_handle);
```

Pins the device configuration to soc_id `35` (QCS6490). This tells the runtime which HTP revision to target — wrong soc_id means the context binary either refuses to load or silently misfires.

---

## 5. Load the context binary

```cpp
std::vector<char> bin_data = read_binary_file(bin_path);
qnn.contextCreateFromBinary(..., bin_data.data(), bin_data.size(), &ctx_handle, ...);
```

This is the most important call. The `.bin` file is the pre-compiled, chip-specific model that was generated by `qnn-context-binary-generator` on the host. Loading it skips the JIT compilation step that would happen with a plain `.dlc`, making startup near-instant on the board. The whole file is read into memory and handed to the runtime.

---

## 6. Retrieve the graph

```cpp
qnn.graphRetrieve(ctx_handle, "resnet50", &graph_handle);
```

A context binary can contain multiple graphs. This retrieves the one named `"resnet50"` — that name must match exactly what was passed to `--binary_file` during context binary generation on the host.

---

## 7. Inspect and wire I/O tensors

```cpp
qnn.graphGetInputs (graph_handle, &input_tensors,  &num_inputs);
qnn.graphGetOutputs(graph_handle, &output_tensors, &num_outputs);

QNN_TENSOR_SET_MEM_TYPE(input_tensors[0],  QNN_TENSORMEMTYPE_RAW);
Qnn_ClientBuffer_t in_cbuf = { input_buf.data(), INPUT_BYTES };
QNN_TENSOR_SET_CLIENT_BUF(input_tensors[0], in_cbuf);
```

The QNN API returns tensor descriptors for all inputs and outputs. Rather than allocating QNN-managed memory, the code uses `QNN_TENSORMEMTYPE_RAW` with a `Qnn_ClientBuffer_t` — this points QNN directly at your own `std::vector` buffers, avoiding an extra copy. The input is a flat float32 array of shape `1×3×224×224` (NCHW), pre-processed with ImageNet mean/std normalization.

---

## 8. Run inference on the NPU

```cpp
qnn.graphExecute(
    graph_handle,
    input_tensors,  num_inputs,
    output_tensors, num_outputs,
    nullptr, nullptr
);
```

This is the single call that dispatches the model to the Hexagon HTP via FastRPC. The CPU blocks until the NPU finishes. The output tensor fills with 1000 raw logit values (one per ImageNet class).

The `QNN_HTP_PERF_INFRASTRUCTURE_POWERMODE_BURST_MODE` set earlier in the context config ensures the HTP clocks are raised to their maximum before this call, giving lowest latency.

---

## 9. Softmax + Top-5 decode

```cpp
float max_val = *std::max_element(output_buf.begin(), output_buf.end());
float sum = 0.0f;
for (auto& v : output_buf) { v = std::exp(v - max_val); sum += v; }
for (auto& v : output_buf) { v /= sum; }

auto top5 = top_k(output_buf.data(), OUTPUT_ELEMS, 5);
```

The logits come out un-normalized. Softmax converts them to probabilities. The `max_val` subtraction before `exp` is a standard numerical stability trick — it prevents float overflow without changing the result. `top_k` then does a partial sort to find the 5 highest-probability classes and prints them with their label strings.

---

## 10. Cleanup

```cpp
qnn.contextFree(ctx_handle, nullptr);
qnn.deviceFree(device_handle);
qnn.backendFree(backend_handle);
qnn.logFree(log_handle);
dlclose(lib);
```

Everything is torn down in reverse order — context before device before backend. `dlclose` unloads the shared library last. Skipping any of these on a long-running process (like a daemon doing continuous inference) would leak handles inside the Hexagon driver.

---
